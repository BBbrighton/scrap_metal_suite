## 1. ภาพรวมธุรกิจ

### ระบบ Scrap Metal Suite คืออะไร?

Scrap Metal Suite เป็นระบบครบวงจรสำหรับจัดการการรับซื้อเศษโลหะ ครอบคลุมทุกขั้นตอน:

1. **ข้อตกลงราคา** — ซัพพลายเออร์ตกลงขายโลหะในราคาที่ล็อคไว้
2. **การส่งมอบ** — ซัพพลายเออร์นำวัตถุดิบมาส่งที่ลานด้วยรถบรรทุก
3. **การชั่งน้ำหนัก** — ชั่งน้ำหนักรถบรรทุก + ชั่งเศษโลหะแต่ละรายการ
4. **การคัดแยกและตรวจสอบคุณภาพ** — ทีมผลิตคัดแยก จัดเกรด และตรวจสอบคุณภาพ
5. **การชำระเงิน** — พนักงานบัญชีจับคู่การส่งมอบกับข้อตกลงราคา สร้างใบซื้อสินค้า

### ทำไมไม่ใช้ Purchase Order มาตรฐานของ ERPNext?

ธุรกิจเศษโลหะมีลักษณะพิเศษที่ไม่เข้ากับระบบมาตรฐาน:

- **ราคาล็อคก่อนส่งมอบ** — ซัพพลายเออร์โทรมาตอนเช้า: "ล็อคทองแดง 10 กก. ที่ 300 บาท/กก." แต่ส่งมอบอีกหลายวันหลังจากนั้น
- **วัตถุดิบที่ส่งมาไม่ตรงกับคำสั่งซื้อ** — ปริมาณเปลี่ยน (ชั่งใหม่ที่ลาน) เกรดลดลงหลังคัดแยก
- **ความสัมพันธ์แบบหลายต่อหลาย** — การส่งมอบครั้งเดียวสามารถเติมเต็มข้อตกลงราคาหลายรายการ ข้อตกลงเดียวสามารถถูกเติมเต็มจากหลายการส่งมอบ
- **ราคาตลาด (Spot)** — วัตถุดิบที่ไม่มีข้อตกลงราคาจะถูกตั้งราคาตามดุลยพินิจของพนักงานบัญชี

### คำศัพท์สำคัญ

| คำศัพท์ | ความหมาย |
|---------|----------|
| **SMT Price Lock** | ข้อตกลงราคา (ใบสั่งซื้อ) "เราจะซื้อ X กก. ของสินค้า Y ในราคา Z บาท/กก." |
| **POS Order** | บันทึกการส่งมอบที่คาดหวัง สร้างอัตโนมัติจาก SMT Price Lock |
| **Dropoff** | เหตุการณ์ส่งมอบสินค้าทางรถบรรทุก หนึ่งคัน หนึ่งซัพพลายเออร์ |
| **Scrap Weight** | บันทึกการชั่งน้ำหนักเศษโลหะแต่ละรายการ |
| **Truck Weight** | น้ำหนักรวม (บรรทุก) และน้ำหนักรถเปล่า (ขนถ่ายแล้ว) |
| **Production Sorting** | ขั้นตอน QC คัดแยกวัตถุดิบเป็นของดีและของเสีย (ตามเกรด) |
| **Dropoff Final** | บันทึกอ้างอิงสุดท้ายของวัตถุดิบที่ได้รับจริงหลังคัดแยก |
| **SMT Purchase Order** | เอกสารกระทบยอดของพนักงานบัญชี จับคู่การส่งมอบกับข้อตกลงราคา |
| **Spot Rate** | ราคาตลาดที่พนักงานบัญชีกำหนดเองสำหรับวัตถุดิบที่ไม่มี PO |

## 2. สถาปัตยกรรมระบบ

### ลำดับการไหลของเอกสาร

```
SMT Price Lock (ข้อตกลงราคา)
  │
  ├──▶ POS Order (สร้างอัตโนมัติ)
  │         │
  │         ▼
  │    Dropoff (รถมาถึง)
  │         │
  │    ┌────┼────────────┐
  │    ▼    ▼            ▼
  │  Truck  Scrap     POS Session
  │  Weight Weight    (ล็อกอินพนักงาน)
  │    │    │
  │    ▼    ▼
  │    Dropoff (Completed)
  │         │
  │         ▼
  │    Production Sorting
  │    (คัดแยก, จัดเกรด, ตรวจสอบ)
  │         │
  │         ▼
  │    Dropoff Final
  │    (ของดี + ของเสีย)
  │         │
  └────────►│
            ▼
       SMT Purchase Order
       (จัดสรรราคา PO + ราคาตลาด)
            │
            ▼
       Purchase Invoice (ฉบับร่าง)
            │
            ▼
       Payment Entry
```

### เทคโนโลยี

- **Backend:** Frappe Framework (Python) + ERPNext
- **ฐานข้อมูล:** MariaDB
- **Frontend:** Frappe Desk + หน้าจอเทอร์มินัลแบบกำหนดเอง (HTML/JS)
- **การเชื่อมต่อเครื่องชั่ง:** WebSerial API (Chrome/Edge) สำหรับเครื่องชั่งอุตสาหกรรม
- **โปรโตคอล:** STX-M, STX, HP-05

## 4. ขั้นตอนการทำงานทั้งหมด

### ขั้นตอนโดยละเอียด

#### ระยะที่ 1: ข้อตกลงราคา

1. ซัพพลายเออร์โทรมา: "ขอล็อคทองแดง 10 กก. ที่ 300 บาท/กก."
2. **พนักงานบัญชี** สร้าง **SMT Price Lock** ในระบบ:
   - ซัพพลายเออร์: ACME Metals
   - สินค้า: ทองแดง, ปริมาณ: 10 กก., ราคา: 300 บาท/กก.
   - ตัวเลือก: กำหนดวันหมดอายุ (หมดอายุอัตโนมัติถ้าซัพพลายเออร์ไม่ส่งมอบ)
3. เมื่อส่ง (Submit):
   - สถานะ PO → **Open** (เปิด)
   - **POS Order** สร้างอัตโนมัติพร้อมสินค้าและปริมาณเดียวกัน
   - ทีมลานสามารถเห็นการส่งมอบที่คาดหวัง

#### ระยะที่ 2: การส่งมอบ

4. ซัพพลายเออร์ขับรถมาที่ลาน
5. **พนักงานชั่ง** เปิด POS Session (ล็อกอินที่เทอร์มินัล)
6. พนักงานสร้าง **Dropoff**:
   - เชื่อมโยงกับ POS Order
   - กรอกทะเบียนรถ เวลานัดหมาย
   - รายการสินค้าที่คาดหวังถูกกรอกอัตโนมัติจาก Order
7. **ชั่งรถบรรทุก:**
   - รถขึ้นเครื่องชั่ง
   - บันทึก **น้ำหนักรวม (Gross)** (รถ + วัตถุดิบ)
   - ขนถ่ายวัตถุดิบ
   - บันทึก **น้ำหนักรถเปล่า (Tare)** (รถเปล่า)
   - ระบบคำนวณ **น้ำหนักสุทธิ** = Gross - Tare
8. **ชั่งเศษโลหะ:**
   - ชั่งแต่ละรายการบนเครื่องชั่งเศษ
   - บันทึกน้ำหนักแต่ละรายการ
   - ระบบติดตามค่าเบี่ยงเบนระหว่างที่คาดหวังกับจริง
9. สถานะ Dropoff เปลี่ยน: Draft → Scheduled → In Progress → **Completed**

#### ระยะที่ 3: ตรวจสอบคุณภาพ

10. **พนักงานคัดแยก** เปิด Production Session
11. สร้าง **Production Sorting** เชื่อมโยงกับ Dropoff:
    - ดูรายการวัตถุดิบที่มาจากการชั่ง
    - คัดแยกเป็น **ของดี** (แยกตามเกรด) และ **ของเสีย** (ปนเปื้อน ผิดชนิด ฯลฯ)
    - ตัวอย่าง: ทองแดง 10 กก. → 9 กก. เกรด A (ดี) + 1 กก. เกรด B (ลดเกรด)
12. ส่งการคัดแยก (Submit)
13. **Dropoff Final** อัปเดตอัตโนมัติ:
    - รวมผลการคัดแยกทั้งหมด
    - คำนวณค่าเบี่ยงเบนเทียบกับน้ำหนักรถ
    - ถ้าค่าเบี่ยงเบนอยู่ในเกณฑ์ (ค่าเริ่มต้น 5%) → สถานะ: **Unsettled** (รอชำระ)
    - ถ้าค่าเบี่ยงเบนเกินเกณฑ์ → สถานะ: **In Progress** (ต้องตรวจสอบ)

#### ระยะที่ 4: การชำระเงิน

14. **พนักงานบัญชี** สร้าง **SMT Purchase Order**:
    - เลือกซัพพลายเออร์: ACME Metals
    - เลือก Dropoff Final ที่ยังไม่ชำระ
    - สร้างตารางจัดสรร:
      - ทองแดงเกรด A 9 กก. → จัดสรรกับ SMT Price Lock ที่ 300 บาท/กก. (ราคาล็อค)
      - ทองแดงเกรด B 1 กก. → ราคาตลาด 285 บาท/กก. (บัญชีกำหนดเอง)
    - ระบบตรวจสอบ: ทุกรายการจัดสรรครบ ไม่จัดสรรเกิน
15. เมื่อส่ง (Submit):
    - `settled_qty` ของ PO อัปเดต (ทองแดง 9/10 → Partially Settled)
    - Dropoff Final → **Settled** (ชำระแล้ว)
    - **ใบซื้อสินค้าฉบับร่าง** สร้างอัตโนมัติ 2,985 บาท
16. พนักงานบัญชีตรวจสอบใบซื้อสินค้าฉบับร่าง กำหนดคลังสินค้า แล้วส่ง
17. สร้าง Payment Entry จ่ายเงินซัพพลายเออร์

#### ระยะที่ 5: ส่งมอบส่วนที่เหลือ

18. ซัพพลายเออร์ส่งมอบทองแดงที่เหลือ 1 กก. ในรถคันที่สอง
19. กระบวนการเดิม: Dropoff → ชั่ง → คัดแยก → Dropoff Final → PO Final
20. `settled_qty` ของ PO ถึง 10/10 → **Fully Settled** (ชำระครบ)

## 5. คู่มือโมดูล: ข้อตกลงราคา (SMT Price Lock)

### วัตถุประสงค์

SMT Price Lock (Scrap Metal Trading Purchase Order) คือข้อตกลงราคา: "เราจะซื้อ X กก. ของสินค้า Y ในราคา Z บาท/กก. จากซัพพลายเออร์นี้"

### การสร้าง SMT Price Lock

1. ไปที่ **SMT Accounting** workspace → **SMT Price Lock** → **New**
2. เลือก **Supplier** (ซัพพลายเออร์)
3. กำหนด **PO Date** (ค่าเริ่มต้นคือวันนี้)
4. กำหนด **Expiry Date** ถ้าต้องการ (PO หมดอายุอัตโนมัติหลังวันนี้)
5. เพิ่มสินค้า:
   | สินค้า | ปริมาณ (กก.) | ราคา (บาท/กก.) |
   |--------|-------------|----------------|
   | ทองแดง | 10 | 300 |
   | อะลูมิเนียม | 5 | 75 |
6. มูลค่า PO รวมคำนวณอัตโนมัติ: 3,375 บาท
7. กด **Submit** (ส่ง)

### สิ่งที่เกิดขึ้นเมื่อส่ง

- สถานะ → **Open** (เปิด)
- **POS Order** สร้างอัตโนมัติพร้อม:
  - ซัพพลายเออร์เดียวกัน
  - วันที่สั่งซื้อเดียวกัน
  - สินค้าและปริมาณเดียวกัน
  - สถานะ: Pending (รอดำเนินการ)
- ทีมลานสามารถเห็นการส่งมอบที่คาดหวัง

### วงจรสถานะ

```
Open → Partially Settled → Fully Settled
  ↘ Expired (อัตโนมัติ ถ้า expiry_date ผ่าน)
  ↘ Cancelled (ยกเลิกเอง เฉพาะเมื่อ settled qty = 0)
```

| สถานะ | ความหมาย |
|-------|----------|
| **Open** | ส่งแล้ว รอการส่งมอบ |
| **Partially Settled** | ชำระบางรายการแล้ว ยังมีปริมาณเหลือ |
| **Fully Settled** | ชำระครบทุกรายการ ไม่ต้องรอการส่งมอบเพิ่ม |
| **Expired** | หมดอายุ เฉพาะ PO ที่สถานะ Open เท่านั้นที่หมดอายุ (ไม่ใช่ Partially Settled) |
| **Cancelled** | ยกเลิก ทำได้เฉพาะเมื่อยังไม่มีการชำระ |

### กฎการยกเลิก

- **ยกเลิกไม่ได้** ถ้ามีรายการที่ชำระแล้ว → ต้องยกเลิก PO Final ก่อน
- เมื่อยกเลิก POS Order ที่สถานะ "Pending" จะถูกยกเลิกอัตโนมัติ
- POS Order ที่กำลังดำเนินการอยู่ (Processing/Processed) จะไม่ถูกยกเลิก

### กฎการหมดอายุ

- ระบบตรวจสอบการหมดอายุทุกวันเวลา 01:00 น.
- เฉพาะ PO ที่สถานะ **Open** และมีวันหมดอายุที่ผ่านมาแล้วเท่านั้นที่จะหมดอายุ
- **PO ที่ Partially Settled จะไม่หมดอายุอัตโนมัติ** — ซัพพลายเออร์ส่งมอบบางส่วนแล้ว
- PO ที่หมดอายุไม่สามารถใช้ในการจัดสรร PO Final

## 6. คู่มือโมดูล: ระบบ POS

### POS Session (เซสชั่น)

พนักงานทุกคนต้องเปิด Session ก่อนเริ่มทำงาน Session ติดตามว่าใครทำอะไรเมื่อไหร่

**การเปิด Session:**
1. ไปที่ `/pos`
2. เลือก POS Profile
3. กด **Open Session**
4. เลือกเครื่องชั่ง (ครั้งเดียวต่อ Session)

**กฎของ Session:**
- เปิดได้ครั้งละ 1 Session ต่อพนักงาน
- ระบบส่ง heartbeat ทุก 30 วินาทีเพื่อติดตามกิจกรรม
- Session ที่ไม่มีกิจกรรมจะปิดอัตโนมัติหลัง 90 นาที (POS) หรือ 10 นาที (Production)
- เครื่องชั่งถูกล็อคกับ Session — พนักงานอื่นใช้ไม่ได้

**การปิด Session:**
- กด **Close Session** ในเทอร์มินัล
- ระบบคำนวณยอดรวมของ Session (จำนวนการชั่ง น้ำหนักรวม)
- เครื่องชั่งถูกปลดล็อคให้พนักงานอื่นใช้ได้

### POS Order

POS Order คือบันทึกการส่งมอบที่คาดหวัง สามารถ:
- **สร้างอัตโนมัติ** จาก SMT Price Lock (เชื่อมผ่านฟิลด์ `smt_price_lock`)
- **สร้างเอง** โดยพนักงานสำหรับซัพพลายเออร์แบบ walk-in

**ฟิลด์:**
| ฟิลด์ | คำอธิบาย |
|-------|----------|
| Supplier | ใครส่งมอบ |
| Order Date | วันที่ (ดึงจาก PO หรือวันนี้) |
| SMT Price Lock | ลิงก์ไปข้อตกลงราคา (ถ้ามี) |
| Order Items | รายการสินค้าที่คาดหวังพร้อมน้ำหนัก |
| Weighed Items | น้ำหนักจริงที่ได้รับ (กรอกอัตโนมัติจาก Dropoff) |
| Fulfillment % | เปอร์เซ็นต์การส่งมอบ |

**สถานะการส่งมอบ:**
| ช่วง % | สถานะ |
|--------|-------|
| 0% | Pending (รอดำเนินการ) |
| 1–97% | Partial (ส่งมอบบางส่วน) |
| 98–102% | Fulfilled (ส่งมอบครบ) |
| >102% | Over-delivered (ส่งมอบเกิน) |

### การเชื่อมต่อเครื่องชั่ง

ระบบรองรับเครื่องชั่งอุตสาหกรรมผ่าน WebSerial API (Chrome/Edge เท่านั้น):

**โปรโตคอลที่รองรับ:**
- **STX-M** — พบบ่อยที่สุด
- **STX** — มาตรฐาน
- **HP-05** — เครื่องชั่งจีน

**การตั้งค่า (Scale DocType):**
| การตั้งค่า | ค่าทั่วไป |
|-----------|----------|
| Baud Rate | 9600 |
| Data Bits | 8 |
| Parity | None |
| Stop Bits | 1 |
| Max Capacity | 500 กก. (เศษ) / 5000 กก. (รถ) |

## 7. คู่มือโมดูล: การส่งมอบและการชั่ง

### Dropoff (การส่งมอบ)

Dropoff คือรถบรรทุกหนึ่งคันที่มาถึงลาน เชื่อมโยงกับ POS Order และบรรจุบันทึกน้ำหนักทั้งหมด

**การสร้าง Dropoff:**
1. เลือกซัพพลายเออร์
2. เชื่อมโยง POS Order — Dropoff หนึ่งรายการสามารถเติมเต็มหลาย Order
3. กรอกทะเบียนรถ
4. กำหนดเวลาเริ่มต้น/สิ้นสุด
5. เพิ่มรายการที่คาดหวัง (ดึงอัตโนมัติจาก Order ที่เชื่อมโยง)

**การเปลี่ยนสถานะ:**
```
Draft → Scheduled → In Progress → Completed
                                   ↘ Cancelled
```

| การเปลี่ยน | เงื่อนไข |
|-----------|---------|
| Draft → Scheduled | กรอกทะเบียนรถ + เวลานัดหมาย |
| Scheduled → In Progress | บันทึกน้ำหนักครั้งแรก (รถหรือเศษ) |
| In Progress → Completed | บันทึกน้ำหนักครบทุกรายการ |

**กฎการไม่เปลี่ยนแปลง:**
- ไม่สามารถเปลี่ยนเวลานัดหมายหลังสถานะเลย Scheduled
- ไม่สามารถลบ Order ที่เชื่อมจาก Dropoff ที่ Completed
- ไม่สามารถลบทะเบียนรถถ้ามีการบันทึกน้ำหนักแล้ว

### การชั่งรถบรรทุก

ต้องชั่ง 2 ครั้งต่อรถ:

1. **น้ำหนักรวม (Gross Weight)** — รถพร้อมวัตถุดิบ
2. **น้ำหนักรถเปล่า (Tare Weight)** — รถเปล่าหลังขนถ่าย

**น้ำหนักสุทธิ (Net Weight)** = Gross - Tare

**การตรวจสอบ:**
- น้ำหนักต้อง > 0
- น้ำหนักต้องไม่เกินพิกัดเครื่องชั่ง
- Tare ต้องน้อยกว่า Gross

**ขั้นตอน:**
1. ไปที่ `/pos/truck`
2. เลือก Dropoff
3. ขับรถขึ้นเครื่องชั่ง → อ่านน้ำหนัก (กรอกเองหรืออ่านจากเครื่องชั่ง)
4. กด **Save Weight** (บันทึกน้ำหนัก)
5. ขนถ่ายวัตถุดิบ
6. ขับรถขึ้นเครื่องชั่งอีกครั้ง
7. สลับไปแท็บ Tare → กด **Save Weight**
8. น้ำหนักสุทธิคำนวณอัตโนมัติ

### การชั่งเศษโลหะ

ชั่งแต่ละรายการบนเครื่องชั่งเศษ

**ขั้นตอน:**
1. ไปที่ `/pos/terminal`
2. ค้นหา Dropoff (ด้วยชื่อ ทะเบียนรถ หรือซัพพลายเออร์)
3. วางวัตถุดิบบนเครื่องชั่ง
4. เลือกประเภทสินค้าจากรายการ
5. บันทึกน้ำหนัก (กรอกเองหรืออ่านจากเครื่องชั่ง)
6. ทำซ้ำสำหรับทุกรายการ
7. ระบบติดตามค่าเบี่ยงเบนเทียบกับน้ำหนักที่สั่งซื้อ

**การชั่งซ้ำ:**
- สามารถโหลดบันทึกชั่งเดิมมาชั่งใหม่ได้
- ต้องระบุเหตุผลการชั่งซ้ำ
- น้ำหนักเดิมถูกเก็บไว้ในประวัติ

## 8. คู่มือโมดูล: การคัดแยกวัตถุดิบ

### วัตถุประสงค์

หลังจากวัตถุดิบมาถึงและถูกชั่งแล้ว ทีมผลิตจะคัดแยกและจัดเกรด ผลลัพธ์จะกำหนดปริมาณและเกรดสุดท้ายสำหรับการชำระเงิน

### Production Session

คล้ายกับ POS Session — พนักงานแต่ละคนต้องเปิด Session ก่อนคัดแยก

**กฎ:**
- เปิดได้ 1 Session ต่อพนักงาน
- ปิดอัตโนมัติหลังไม่มีกิจกรรม 10 นาที
- สามารถกำหนดเครื่องชั่งสำหรับการชั่งดิจิทัลระหว่างคัดแยก

### การสร้างบันทึกการคัดแยก

1. เปิดเทอร์มินัล Production ที่ `/production/terminal`
2. ค้นหา Dropoff ที่สถานะ Completed
3. ดูรายการวัตถุดิบต้นทาง (ที่มาจากการชั่ง)
4. คัดแยกเป็น:
   - **ของดี (Good Items)** — วัตถุดิบที่ผ่าน QC (รหัสสินค้า น้ำหนัก หมายเหตุ)
   - **ของเสีย (Unwanted Items)** — วัตถุดิบที่ถูกปฏิเสธ (รหัสสินค้า น้ำหนัก เหตุผล หมายเหตุ)

**เหตุผลการคืนสำหรับของเสีย:**
- Contamination (ปนเปื้อน)
- Wrong Material (ผิดชนิด)
- Packaging (มีบรรจุภัณฑ์ปน)
- Dirt/Debris (สิ่งสกปรก/เศษวัสดุ)
- Other (อื่นๆ เช่น "ลดเกรดเป็น Grade B")

**ตัวอย่าง:**
| วัตถุดิบต้นทาง | ของดี | ของเสีย |
|---------------|-------|--------|
| ทองแดง 10.2 กก. | ทองแดงเกรด A 9.0 กก. | ทองแดงเกรด B 1.0 กก. (Other: ลดเกรด) |
| | | ทองแดง 0.2 กก. (Contamination: เคลือบพลาสติก) |
| อะลูมิเนียม 4.5 กก. | อะลูมิเนียมแผ่น 4.5 กก. | — |

### การส่งการคัดแยก

- เมื่อส่ง (Submit) Dropoff Final จะอัปเดตอัตโนมัติ
- ของดีและของเสียถูกรวมตามรหัสสินค้า
- ยอดรวมและค่าเบี่ยงเบนถูกคำนวณใหม่

### การ Override ของผู้จัดการ

- Production Manager สามารถ override ค่าเบี่ยงเบน
- ผู้จัดการสามารถปิด Session ที่เปิดโดยพนักงานอื่น

## 9. คู่มือโมดูล: การชำระเงิน (SMT Purchase Order)

### วัตถุประสงค์

SMT Purchase Order คือเอกสารกระทบยอดของพนักงานบัญชี จับคู่การส่งมอบจริง (Dropoff Final) กับข้อตกลงราคา (SMT Price Lock) และสร้างใบซื้อสินค้า

### การสร้าง PO Final

1. ไปที่ **SMT Accounting** workspace → **SMT Purchase Order** → **New**
2. เลือก **Supplier** (ซัพพลายเออร์)
3. **ตาราง Dropoff Finals** — เลือก Dropoff Final ที่ยังไม่ชำระ
4. **ตารางจัดสรร** — หัวใจของการชำระเงิน:

สำหรับแต่ละรายการใน Dropoff Final:
| การดำเนินการ | แหล่งที่มา | ราคา |
|-------------|----------|------|
| จัดสรรกับ PO | เลือก PO จากดร็อปดาวน์ | ล็อคอัตโนมัติตามราคา PO |
| ตั้งราคาตลาด | เลือก "Spot" | กรอกราคาเอง |

### กฎการจัดสรร

1. **ต้องจัดสรรครบ** — ทุกรายการในทุก Dropoff Final ต้องถูกจัดสรร ไม่มีการชำระบางส่วนของ Dropoff
2. **ห้ามจัดสรรเกิน** — ไม่สามารถจัดสรรมากกว่าปริมาณที่เหลือของ PO
3. **ราคาล็อค** — เมื่อแหล่งที่มาคือ PO ราคามาจาก PO และเปลี่ยนไม่ได้
4. **ราคาตลาดต้อง > 0** — ต้องกรอกราคาเองสำหรับ Spot
5. **ซัพพลายเออร์ต้องตรงกัน** — PO และ Dropoff Final ทั้งหมดต้องเป็นของซัพพลายเออร์เดียวกัน
6. **ห้ามชำระซ้ำ** — Dropoff Final ที่สถานะ "Settled" แล้วไม่สามารถใช้ซ้ำ

### การแบ่งการจัดสรร

ถ้ารายการเดียวใน Dropoff Final ต้องแบ่งไปสอง PO (ราคาต่างกัน) ให้เพิ่มสองแถวจัดสรรสำหรับรายการเดียวกัน แต่ละแถวชี้ไป PO ต่างกัน ยอดรวมต้องเท่ากับปริมาณใน Dropoff Final

### สิ่งที่เกิดขึ้นเมื่อส่ง (Submit)

1. **PO อัปเดต** — `settled_qty` เพิ่มขึ้นแบบ atomic ในแต่ละรายการ PO
2. **สถานะ PO คำนวณใหม่** — Open → Partially Settled → Fully Settled
3. **Dropoff Final ถูกทำเครื่องหมายเป็น Settled** — สถานะ, po_final link, settled_by, settled_at
4. **ใบซื้อสินค้าฉบับร่างสร้างอัตโนมัติ** — พร้อมรายการจากการจัดสรร
5. **สถานะ PO Final → Submitted**

### สิ่งที่เกิดขึ้นเมื่อยกเลิก (Cancel)

1. ใบซื้อสินค้าฉบับร่างถูกลบ (ถ้ายังเป็นร่าง)
2. ถ้าใบซื้อสินค้าถูกส่งแล้ว → ยกเลิกไม่ได้ ("ยกเลิก Purchase Invoice ก่อน")
3. `settled_qty` ของ PO คืนค่า
4. สถานะ PO คำนวณใหม่
5. Dropoff Final คืนเป็น Unsettled
6. สถานะ PO Final → Cancelled

### การป้องกันการยกเลิก (Frappe Cascade)

เมื่อ Payment Entry ถูกส่งสำหรับใบซื้อสินค้า:
```
ยกเลิก PO Final ไม่ได้
  ← เพราะ PI ถูกส่งแล้ว
    ← เพราะ Payment Entry ถูกส่งแล้ว
```

วิธีย้อนกลับ: ยกเลิก Payment Entry → ยกเลิก PI → ยกเลิก PO Final (ลำดับย้อนกลับ)

### การแก้ไข PO Final

ใช้กระบวนการ Amend มาตรฐานของ Frappe:
1. ยกเลิก PO Final
2. กด **Amend** → สร้างเวอร์ชันใหม่ (POF-...-1)
3. แก้ไขการจัดสรร
4. ส่ง (Submit)
5. ประวัติการแก้ไขถูกเก็บผ่าน `amended_from`

## 10. ค่าเบี่ยงเบนและการตรวจสอบ

### ประเภทค่าเบี่ยงเบน

ระบบติดตามค่าเบี่ยงเบนหลายระดับ:

#### 1. ค่าเบี่ยงเบนระหว่างรถกับเศษ

เปรียบเทียบน้ำหนักสุทธิรถกับน้ำหนักเศษรวม

```
น้ำหนักสุทธิรถ:      15.0 กก. (Gross 2500 - Tare 2485)
น้ำหนักเศษรวม:       14.7 กก. (ผลรวมการชั่งเศษแต่ละรายการ)
ค่าเบี่ยงเบน:         0.3 กก. (2.0%)
```

**สาเหตุ:** วัตถุดิบร่วงระหว่างขนถ่าย ความต่างของการสอบเทียบเครื่องชั่ง ความชื้นระเหย

#### 2. ค่าเบี่ยงเบนระหว่างที่ระบุกับจริง

เปรียบเทียบสิ่งที่ซัพพลายเออร์แจ้ง (น้ำหนักตาม POS Order) กับที่ชั่งจริง

```
ตามสัญญา:    15.0 กก. (จาก POS Order)
ที่ชั่งจริง:    14.7 กก. (จากการชั่งเศษ)
ค่าเบี่ยงเบน:  -0.3 กก. (-2.0%)
```

#### 3. ค่าเบี่ยงเบนการคัดแยก (Dropoff Final)

เปรียบเทียบน้ำหนักรวม Dropoff กับน้ำหนักที่คัดแยกรวม

```
น้ำหนัก Dropoff:      14.7 กก.
ของดีรวม:            13.5 กก.
ของเสียรวม:           1.2 กก.
น้ำหนักตรวจสอบรวม:    14.7 กก.
ค่าเบี่ยงเบน:          0.0 กก. (0.0%)
```

### เกณฑ์ค่าเบี่ยงเบน

ตั้งค่าใน **Production Sorting Settings**:
- ค่าเริ่มต้น: **5%**
- ถ้าค่าเบี่ยงเบน % ≤ เกณฑ์ → **Variance OK** Dropoff Final → **Unsettled** (พร้อมชำระ)
- ถ้าค่าเบี่ยงเบน % > เกณฑ์ → **Needs Review** Dropoff Final ยังอยู่ **In Progress**
- ผู้จัดการต้องตรวจสอบและอนุมัติด้วยตนเองก่อนชำระ

### สถานะการตรวจสอบ

| สถานะ | ความหมาย |
|-------|----------|
| **Pending** | ยังไม่มีการคัดแยก |
| **Verified** | ค่าเบี่ยงเบนอยู่ในเกณฑ์ — อนุมัติอัตโนมัติ |
| **Needs Review** | ค่าเบี่ยงเบนเกินเกณฑ์ — ต้องให้ผู้จัดการตรวจสอบ |

## 11. การพิมพ์เอกสาร

### รูปแบบการพิมพ์ที่มี

| รูปแบบ | DocType | คำอธิบาย |
|--------|---------|----------|
| ใบยืนยันราคา (Price Lock) | SMT Price Lock | ซัพพลายเออร์ รายการล็อคราคาพร้อมอัตรา/ชำระ/คงเหลือ ยอดรวม ลายเซ็น |

| ใบคัดแยก (Sorting Report) | Dropoff Final | ของดี ของเสียพร้อมเหตุผล สรุปค่าเบี่ยงเบน (ผ่าน/ไม่ผ่าน) |

| ใบสรุปการส่งมอบ (Delivery Summary) | POS Order | รายการสั่ง รายการที่ชั่ง สถานะการส่งมอบ |
| Scrap Weight Thermal | Scrap Weight | ใบเสร็จ thermal 80mm สำหรับการชั่งเศษแต่ละรายการ |
| Truck Weight Thermal | Truck Weight | ใบเสร็จ thermal 80mm สำหรับการชั่งรถ |

รูปแบบ A4 ทั้งหมดเป็นสองภาษา (ไทย/อังกฤษ) พร้อมหัวจดหมายบริษัท QR code และช่องลายเซ็น
รูปแบบ thermal ขนาด 80mm สำหรับเครื่องพิมพ์ใบเสร็จ

### การพิมพ์จากเทอร์มินัล

- ในเทอร์มินัล POS กด **Print** หลังบันทึกน้ำหนัก
- เปิดกล่องโต้ตอบพิมพ์ของเบราว์เซอร์
- รองรับเครื่องพิมพ์ thermal (ตั้งค่าขนาดกระดาษในเบราว์เซอร์)

### การพิมพ์ซ้ำ

- เอกสารที่ส่งแล้วสามารถพิมพ์ซ้ำได้จาก Frappe Desk
- ไปที่เอกสาร → **Menu** → **Print**
- เลือกรูปแบบการพิมพ์ → **Print** หรือ **PDF**

## 12. งานอัตโนมัติ (Cron Jobs)

### งานอัตโนมัติที่ใช้งาน

| งาน | กำหนดเวลา | สิ่งที่ทำ |
|-----|----------|---------|
| **ปิด POS Session ที่ไม่มีกิจกรรม** | ทุก 15 นาที | ปิด POS Session ที่ไม่มีกิจกรรมเกิน 90 นาที ปลดล็อคเครื่องชั่ง |
| **ปิด Production Session ที่ไม่มีกิจกรรม** | ทุก 5 นาที | ปิด Production Session ที่ไม่มีกิจกรรมเกิน 10 นาที ปลดล็อคเครื่องชั่ง |
| **หมดอายุ PO ที่เปิดอยู่** | ทุกวันเวลา 01:00 น. | หมดอายุ SMT Price Lock ที่สถานะ "Open" และ expiry_date ผ่านแล้ว ไม่หมดอายุ PO ที่ Partially Settled |

### การตรวจจับความไม่มีกิจกรรม

- แต่ละเทอร์มินัลส่ง **heartbeat** ทุก 30 วินาที (ผ่าน API `update_session_activity`)
- ระบบเปรียบเทียบ `last_activity` กับเกณฑ์
- ถ้า `last_activity` เก่ากว่าเกณฑ์ Session จะปิดอัตโนมัติ
- พนักงานจะเห็นคำเตือนในเทอร์มินัลว่า Session ถูกปิดแล้ว
- ต้องเปิด Session ใหม่เพื่อทำงานต่อ

### รายละเอียดการปิด Session อัตโนมัติ

เมื่อ Session ถูกปิดอัตโนมัติ:
1. สถานะ Session → **Closed**
2. เวลาปิดถูกกำหนดเป็นเวลาปัจจุบัน
3. ปิดโดย → "Administrator"
4. ถ้ามีเครื่องชั่งที่กำหนดไว้ จะถูกปลดล็อค (`in_use = 0`, `in_use_by_session = None`)

## 14. คู่มือ: พนักงานชั่ง (POS Operator)

### หน้าที่ของคุณ

คุณเป็นพนักงานลาน ชั่งรถบรรทุก ชั่งเศษโลหะ และบันทึกการส่งมอบ

### ขั้นตอนการทำงานประจำวัน

1. **เริ่มกะ:** ไปที่ `/pos` → เปิด Session → เลือกเครื่องชั่ง
2. **เมื่อรถมาถึง:**
   - ค้นหา POS Order (ด้วยชื่อ ทะเบียนรถ หรือ scan QR)
   - สร้าง Dropoff ถ้ายังไม่มี
   - บันทึกน้ำหนักรวม (รถบนเครื่องชั่ง)
   - ขนถ่ายวัตถุดิบ
   - บันทึกน้ำหนักรถเปล่า (รถเปล่าบนเครื่องชั่ง)
3. **ชั่งรายการ:**

   - เลือกประเภทสินค้า → วางบนเครื่องชั่ง → บันทึกน้ำหนัก
   - ทำซ้ำสำหรับทุกรายการ

**แผงซ้าย — บันทึกน้ำหนัก:**
- **แท็บ Gross/Tare** — สลับระหว่างสองประเภทน้ำหนัก
- หลังบันทึกน้ำหนัก ✓ ยืนยันปรากฏพร้อมเวลาและวิธีการ

- **ส่งมอบเสร็จ** — เปลี่ยนสถานะ Dropoff เป็น Completed (หลังบันทึกทั้งสองน้ำหนักเท่านั้น)

**แผงขวา — การตรวจสอบ:**

- **น้ำหนักเศษ** — รายการน้ำหนักเศษที่ย่อ/ขยายได้

### เคล็ดลับ

- ตรวจสอบทะเบียนรถให้ตรงกับ Dropoff เสมอ
- ถ้าค่าเครื่องชั่งดูผิดปกติ ให้ชั่งซ้ำ (ระบุเหตุผล)
- ถ้า Session หมดเวลา (90 นาทีไม่มีกิจกรรม) เปิด Session ใหม่ได้เลย
- ใช้โหมดมืดสำหรับสภาพแวดล้อมกลางแจ้ง/แสงจ้า
- ปุ่ม **Print** พิมพ์ใบบันทึกน้ำหนักล่าสุดซ้ำ
- ปุ่ม **Summary** แสดงยอดรวม Session (จำนวนการชั่ง น้ำหนักรวม)

### สิ่งที่คุณทำไม่ได้

- สร้างหรือแก้ไข SMT Price Lock (ข้อตกลงราคา)
- สร้าง Production Sorting (เป็นหน้าที่ทีมคัดแยก)
- สร้าง PO Final (เป็นหน้าที่พนักงานบัญชี)
- ดูข้อมูลการชำระเงิน

## 15. คู่มือ: พนักงานคัดแยก (Production Worker)

### หน้าที่ของคุณ

คุณคัดแยกและจัดเกรดวัตถุดิบหลังจากมาถึง คุณกำหนดว่าอะไรคือคุณภาพดีและอะไรต้องถูกปฏิเสธหรือลดเกรด

### ขั้นตอนการทำงานประจำวัน

1. **เริ่มกะ:** ไปที่ `/production/terminal` → เปิด Session
2. **เมื่อวัตถุดิบพร้อมคัดแยก:**
   - ค้นหา Dropoff ที่สถานะ Completed
   - ดูรายการต้นทาง (ที่มาจากการชั่ง)
   - คัดแยกวัตถุดิบจริง
   - บันทึกของดีพร้อมน้ำหนัก
   - บันทึกของเสียพร้อมเหตุผล
   - ส่งการคัดแยก
3. **สิ้นสุดกะ:** ปิด Session (หรือปิดอัตโนมัติหลัง 10 นาทีไม่มีกิจกรรม)

- Session ของคุณปิดอัตโนมัติหลัง **10 นาที** ที่ไม่มีกิจกรรม (สั้นกว่า POS)

- สร้าง PO หรือชำระเงิน (เป็นหน้าที่พนักงานบัญชี)

## 16. คู่มือ: พนักงานบัญชี (SMT Accountant)

### หน้าที่ของคุณ

คุณจัดการข้อตกลงราคา กระทบยอดการส่งมอบกับข้อตกลง และสร้างใบซื้อสินค้า

### ขั้นตอนการทำงานประจำวัน

1. **ข้อตกลงราคา:** สร้าง SMT Price Lock เมื่อซัพพลายเออร์โทรมาล็อคราคา
2. **การชำระเงิน:** เมื่อสิ้นวัน (หรือเมื่อ Dropoff Final พร้อม):
   - ไปที่ SMT Accounting workspace
   - ตรวจสอบ Dropoff Final ที่ยังไม่ชำระ
   - สร้าง SMT Purchase Order สำหรับแต่ละซัพพลายเออร์
   - จัดสรรรายการกับ PO หรือราคาตลาด
   - ส่ง → ใบซื้อสินค้าฉบับร่างสร้างอัตโนมัติ
3. **ตรวจสอบใบซื้อสินค้า:** เปิดใบซื้อสินค้าฉบับร่าง ตรวจสอบ กำหนดคลังสินค้า แล้วส่ง
4. **จ่ายเงิน:** สร้าง Payment Entry

### Workspace ของคุณ

**SMT Accounting** workspace มี:
- **ทางลัด:** SMT Price Lock ใหม่, SMT Purchase Order ใหม่
- **การ์ดการชำระ:** SMT Price Lock, SMT Purchase Order
- **การ์ดอ้างอิง:** Dropoff Final, Dropoff, Production Sorting, Scrap Purchase, Truck Weight

- POS Order — เพื่อดูปริมาณตามสัญญา

### การเชื่อมโยง Dashboard

เมื่อดู SMT Price Lock แถบข้างแสดง:
- **Orders** → POS Order ที่สร้างจาก PO นี้
- **Settlement** → PO Final ที่จัดสรรกับ PO นี้

เมื่อดู SMT Purchase Order แถบข้างแสดง:
- **Settlement** → SMT Price Lock และ Dropoff Final ที่อ้างอิง
- **Accounting** → Purchase Invoice ที่เชื่อมโยง

### เคล็ดลับ

- ตรวจสอบสถานะการตรวจสอบของ Dropoff Final ก่อนชำระเสมอ
- ถ้า Dropoff Final แสดง "Needs Review" ให้ประสานกับ Production Manager
- ใช้ราคาตลาด (Spot) เฉพาะวัตถุดิบที่ไม่มี PO เท่านั้น
- ถ้าทำผิดพลาด ยกเลิก PO Final (ซึ่งลบใบซื้อสินค้าฉบับร่าง) แล้วแก้ไขและส่งใหม่
- ราคา PO ถูกล็อค — คุณเปลี่ยนราคาในการจัดสรรไม่ได้

### สิ่งที่คุณทำไม่ได้

- แก้ไขบันทึก Dropoff หรือน้ำหนัก (สิทธิ์อ่านอย่างเดียว)
- สร้างหรือแก้ไข Production Sorting
- เปิด POS หรือ Production Session

## 17. คู่มือ: ผู้จัดการ (Manager)

  - การตั้งค่าเครื่องชั่ง
  - POS Profile
  - บทบาทและสิทธิ์ผู้ใช้
- สามารถรันการทดสอบและจัดการงานอัตโนมัติ

## 19. การแก้ไขปัญหา

### เครื่องชั่งเชื่อมต่อไม่ได้

1. ตรวจสอบการเชื่อมต่อ USB
2. ตรวจสอบว่าใช้เบราว์เซอร์ Chrome/Edge (ต้องการ WebSerial)
3. ไปที่ `/scale-test` เพื่อวินิจฉัย
4. ตรวจสอบการตั้งค่าเครื่องชั่ง: baud rate, data bits, parity, stop bits
5. ลอง auto-detect เพื่อระบุโปรโตคอล

### Session หมดเวลา / ปิดอัตโนมัติ

- POS Session ปิดอัตโนมัติหลัง 90 นาทีที่ไม่มีกิจกรรม
- Production Session ปิดอัตโนมัติหลัง 10 นาที
- เปิด Session ใหม่ได้เลย — งานก่อนหน้าถูกบันทึกไว้แล้ว

### ข้อผิดพลาด "ยกเลิกไม่ได้"

| ข้อผิดพลาด | วิธีแก้ |
|-----------|--------|
| "settled quantity exists" | ยกเลิก PO Final ที่อ้างอิง PO นี้ก่อน |
| "Purchase Invoice is submitted" | ยกเลิก PI ก่อน แล้วยกเลิก PO Final |
| "Payment Entry linked" | ยกเลิก Payment Entry ก่อน แล้ว PI แล้ว PO Final |
| "Dropoff Final already settled" | ยกเลิก PO Final ที่ชำระ DOF นี้ก่อน |

### ค่าเบี่ยงเบนสูงเกินไป

- ตรวจสอบว่าวัตถุดิบถูกคัดแยกถูกต้อง
- ตรวจสอบการสอบเทียบเครื่องชั่ง
- เปรียบเทียบน้ำหนักสุทธิรถกับเศษรวม
- Production Manager อาจต้อง override

### POS Order แสดงการส่งมอบผิด

- การส่งมอบคำนวณอัตโนมัติจากน้ำหนัก Dropoff ที่เชื่อมโยง
- ถ้า Dropoff ถูกยกเลิก การส่งมอบจะคำนวณใหม่
- ตรวจสอบว่า Dropoff ทั้งหมดเชื่อมโยงกับ Order ถูกต้อง
